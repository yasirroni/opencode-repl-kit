## Improve Project Documentation Structure

Split the original monolithic `PLAN.md` into four focused documents: `PLAN.md` for active planning and demo scenarios, `EXECUTED.md` for completed work and decisions, `OVERVIEW.md` for project context and goals, and `ARCHITECTURE.md` for structural documentation. This separation makes it easier to find relevant information — planning stays forward-looking, execution history captures rationale, and architecture provides a reference for the codebase layout. The decision was made to avoid a single growing file that mixes concerns, which becomes harder to maintain as the project evolves.

## Adopt opencode-pty Plugin for REPL Sessions

Chose the [opencode-pty](https://github.com/shekohex/opencode-pty) plugin to enable persistent interactive terminal sessions. This was selected over alternatives (like running scripts via `bash` tool) because it maintains state between commands, which is essential for REPL workflows where variables and imports need to persist. The plugin provides `pty_spawn`, `pty_write`, `pty_read`, and `pty_kill` primitives that map directly to terminal interaction patterns.

## Separate MATLAB, Python, and Julia Projects

Kept MATLAB, Python, and Julia as independent subprojects under `matlab/`, `python/`, and `julia/` rather than attempting cross-language integration. This decision reflects the project's goal of demonstrating opencode's ability to work with multiple language environments independently, not building a polyglot system. Each subproject mirrors the same structure (scripts + package) to make comparisons straightforward.

## Use JSON for Data Interchange

Standardized on JSON as the data format for both MATLAB and Python outputs. JSON is natively supported in Python and can be handled in MATLAB via built-in functions or toolboxes. This choice ensures data generated by one language's scripts could theoretically be consumed by the other, even though cross-language integration is not a current goal.

## MATLAB Setup via Shell Alias

Configured MATLAB access through a `~/.zshrc` alias: `matlab="/Applications/MATLAB_R2025b.app/bin/matlab -nojvm -nodesktop"`. The `-nojvm` and `-nodesktop` flags reduce startup time and resource usage, which is important for REPL sessions that need to start quickly. This avoids requiring the full MATLAB GUI environment.

## Python Environment via uv

Used `uv` for Python environment management (`uv venv env && source env/bin/activate`). uv was chosen over plain `venv` + `pip` for its speed and deterministic resolution. The virtual environment lives at `python/env/` and is excluded from version control via `.gitignore`.

## Implement MATLAB PackageName Package

Created the MATLAB `PackageName` package at `matlab/PackageName/` with 11 files mirroring the Python `packagename` package. The main `PackageName.m` is a `classdef` handle class with `data` and `metadata` properties, providing methods: `filterData`, `filterRange`, `sumAgg`, `meanAgg`, `countAgg`, `minAgg`, `maxAgg`, and `summary`. Filter methods return new `PackageName` instances for method chaining, matching Python's behavior.

Standalone functions were created as individual `.m` files (MATLAB requires file name to match primary function name): `filterData.m`, `filterRange.m`, `sum_agg.m`, `mean_agg.m`, `count_agg.m`, `min_agg.m`, `max_agg.m`, `has_nulls.m`, `validate_types.m`, `check_ranges.m`. Each handles both numeric arrays and struct arrays, with NaN-aware aggregation (matching Python's `None` handling).

Verified via `temp/verify_packagename.m` running in MATLAB `-batch` mode: all 9 test categories passed — creation, filtering, range filtering, aggregations, summary, empty data, NaN handling, struct arrays, and validation. Output parity confirmed: `filterData('>', 2)` returns `[3, 4, 5]`, `meanAgg()` returns `3`, matching Python exactly.

Decision: used individual `.m` files per function rather than combining into fewer files, because MATLAB requires the primary function name to match the file name. This is more files than Python but follows MATLAB conventions.

## EDA Showcase: Spatial Network EDA via REPL

### What Was Built

**Data generation** (`scripts/generate_data.py`):
- `data/grid_data.nc` — 50×50×10 atmospheric grid (elevation, temperature, pressure, humidity) with ~5% NaN
- `data/nodes.arrow` — 200 network nodes (location, elevation, measured_temp/pressure/humidity) with ~3% NaN
- `data/edges.arrow` — 500 directed edges (distance_km, weight, terrain_factor, elevation_change)
- Dependencies: `numpy netCDF4 pyarrow scipy xarray matplotlib pandas` via `uv pip install`

**EDA via persistent REPL** (IPython session, one spawn, all phases in memory):
- Phase A: Load all data, inspect shapes/dtypes/NaN counts
- Phase B: Grid exploration — vertical profiles, horizontal slices, terrain elevation, zonal mean
- Phase C: Network topology — degree distribution (in/out/total), Union-Find connected components (10 components, 6 isolated nodes), node type/region breakdown
- Phase D: Node-grid integration — nearest-neighbor lookup, elevation residual (RMSE=0), temperature residual (RMSE=1.56K, 11 outliers), spatial autocorrelation
- Phase E: Edge analysis — weight vs distance correlation (r=0.914), elevation change distribution, bottleneck edges (125 >75th percentile)
- Phase F: Network graph visualization with directional arrows, summary stat plots
- Phase G: Consolidated into `scripts/eda_spatial_network.py` with `# %%` jupytext-compatible cell blocks

**New artifacts**:
- `.opencode/skills/PYTHON_REPL_EDA.md` — EDA-specific REPL patterns: xarray lazy loading, pyarrow IPC, matplotlib Agg backend, pandas exploration, scipy sparse graphs, `# %%` block conventions, iterative refinement pattern
- `.opencode/prompts/EXPLORATORY_DATA_ANALYSIS.md` — independent agent prompt for Stage 2

### Key Decisions

1. **Single persistent REPL session** — all data loaded once at Phase A, no re-loading across 6 phases. This directly demonstrates the core REPL advantage over package-based approaches.

2. **Iterative refinement via `exec(open('temp/...').read()`)** — each phase started as a temp file. Errors (e.g., wrong xarray dimension reduction, shape mismatch in zonal mean) were fixed by editing the file and re-executing, rather than re-typing. This is the canonical REPL workflow.

3. **xarray `describe()` on Dataset** — discovered that `xarray.Dataset` has NO `.describe()` method. Must use `ds.to_dataframe().describe()` instead. This was added to PYTHON_REPL_EDA.md as a verified gotcha.

4. **Union-Find for connected components** — used pure numpy implementation (no scipy dependency needed) for clarity and speed. Works well for ~200 nodes.

5. **`matplotlib.use('Agg')` before `pyplot`** — mandatory for PTY. Verified in PYTHON_REPL_EDA.md pitfalls table.

6. **Spatial autocorrelation** — simplified to distance-binned autocorrelation rather than full correlogram, since the pairwise matrix for 186 valid nodes is large. Reports weak autocorr at all distance scales.

### Skills Updated

**PYTHON_REPL_EDA.md** new sections:
- xarray `describe()` gotcha (Dataset has no describe, use to_dataframe)
- pcolormesh shading parameter (use 'auto' to avoid shape mismatch)
- arrow plotting performance note (use LineCollection for large graphs)
- Verified xarray patterns table with `sel(alt=float(...))` conversion

## Python & MATLAB Backspace Investigation — Completed

### Python REPL Backspace Findings

| Test | Result |
|------|--------|
| `\x7f` at empty prompt | No-op |
| `\x7f` with text | Deletes character before cursor |
| Multiple `\x7f` | Sequentially deletes characters |
| `\x7f` in continuation `...` | Deletes character, can damage original line |
| Ctrl+C (`\x03`) in continuation | **Clean exit** — returns to `>>>` with `KeyboardInterrupt` |

**Key finding**: Backspace `\x7f` works as character delete, but **Ctrl+C is better for canceling continuation** — it cleanly exits without risking damage to the original line.

### MATLAB REPL Backspace Findings

| Test | Result |
|------|--------|
| `\x7f` (DEL) at prompt | Literal `` character, NOT processed as backspace |
| `\x08` (BS, Ctrl+H) with text | Deletes character before cursor |
| Multiple `\x08` | Sequentially deletes characters |
| `\x08` in continuation `...` | Deletes character |
| Ctrl+C (`\x03`) in continuation | Clean exit — returns to `>> ` |

**Key finding**: MATLAB uses `\x08` (ASCII BS, Ctrl+H) for backspace, NOT `\x7f` (ASCII DEL). This is a platform/terminal difference.

## Clear Line / Line Editing Investigation — Completed

### Python REPL Line Editing Keys

| Key | Code | Tested | Result |
|-----|------|--------|--------|
| Backspace | `\x7f` | ✓ | Deletes char before cursor |
| Ctrl+U | `\x15` | ✓ | **Clears entire line** (kill to beginning) |
| Ctrl+K | `\x0b` | ✓ | No visible effect |
| Ctrl+A | `\x01` | ✓ | **Moves cursor to beginning** |
| Ctrl+E | `\x05` | | Not tested |

**Key finding**: Ctrl+U (`\x15`) reliably clears the entire typed line in Python REPL. Useful for clearing mistakes quickly.

### MATLAB REPL Line Editing Keys

| Key | Code | Tested | Result |
|-----|------|--------|--------|
| Backspace | `\x08` | ✓ | Deletes char before cursor |
| Ctrl+U | `\x15` | ✓ | No effect (literal chars printed) |
| Ctrl+K | `\x0b` | ✓ | No visible effect |
| Ctrl+A | `\x01` | ✓ | No effect |
| Cancel | `\x03` | ✓ | **Clears line** and returns to `>> ` |

**Key finding**: MATLAB REPL does NOT process Ctrl+U, Ctrl+K, Ctrl+A for line editing. Only `\x08` (backspace) and `\x03` (cancel) work.

### Julia REPL Line Editing Keys

| Key | Code | Tested | Result |
|-----|------|--------|--------|
| Backspace | `\x7f` | ✓ | Deletes char before cursor (multiple work sequentially) |
| Ctrl+U | `\x15` | ✓ | **Clears entire line** (kill to beginning) |
| Ctrl+K | `\x0b` | ✓ | **Kills from cursor to end** |
| Ctrl+A | `\x01` | ✓ | **Moves cursor to beginning** |
| Ctrl+E | `\x05` | ✓ | **Moves cursor to end** |
| Cancel | `\x03` | ✓ | Cancels continuation, prints `^C`, returns to `julia>` |

**Key finding**: Julia REPL has FULL ANSI terminal line-editing support — same as Python. All Ctrl+U/K/A/E work. Only special: `\x7f` also exits `pkg>` mode.

### Cross-Language Summary

| Feature | Python | MATLAB | Julia |
|---------|--------|--------|-------|
| Backspace | `\x7f` DEL | `\x08` BS | `\x7f` (also exits `pkg>`) |
| Clear line | `\x15` Ctrl+U ✓ | ❌ none | ✓ Ctrl+U |
| Kill to end | `\x0b` Ctrl+K ~ | ❌ none | ✓ Ctrl+K |
| Move toBOL | `\x01` Ctrl+A ✓ | ❌ none | ✓ Ctrl+A |
| Move to EOL | `\x05` Ctrl+E ✓ | ❌ none | ✓ Ctrl+E |
| Cancel | `\x03` Ctrl+C ✓ | `\x03` Ctrl+C ✓ | `\x03` Ctrl+C ✓ |

## REPL Spawn Detection — Environment Awareness

Replaced hardcoded binary paths in all REPL skills with environment-aware detection logic. Each base `*-repl` skill is now the single source of truth for spawn detection; all other files reference it.

### MATLAB Binary Detection (`matlab-repl/SKILL.md`)

- **macOS**: Glob `/Applications/MATLAB_*.app/bin/matlab` — auto-picks highest version if multiple found
- **Windows**: `matlab` is typically on PATH
- **Linux**: `/usr/local/MATLAB/R20*b/bin/matlab` or PATH
- If none found → asks user for the path
- Always uses `-nojvm -nodesktop` flags

### Python Environment Detection (`python-repl/SKILL.md`)

- Globs for `**/env/bin/python`, `**/.venv/bin/python`, `**/venv/bin/python`
- After spawn: verifies isolation via `import sys; print(sys.prefix)` — warns if running outside venv
- If no venv but project markers exist (`uv.lock`, `pyproject.toml`, `requirements.txt`) → asks user to create one
- Never uses system `python3`

### Julia Binary + Project Detection (`julia-repl/SKILL.md`)

- Binary: tries `~/.juliaup/bin/julia`, falls back to `julia` (PATH)
- Project: globs for `**/Project.toml` (excluding system-level `~/.julia/`), auto-activates via `--project=<dir>` flag
- Prevents `] add` from polluting `~/.julia/packages/`
