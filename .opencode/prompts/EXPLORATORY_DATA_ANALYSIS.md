# Exploratory Data Analysis — Language-Agnostic REPL Workflow

> This document describes the phase-based REPL EDA workflow that applies to **any language REPL** (Python, Julia, MATLAB). It is language-agnostic — the principle of state preservation across exploration phases is universal. See language-specific skill files for package-level patterns.

---

## Core REPL EDA Principle

**State preservation is everything.** In a REPL EDA session:
- Load all data ONCE at the start
- All data stays in memory across all exploration phases
- Each exploration step builds on previous state
- Write intermediate results to temp files for refinement, then consolidate

This is fundamentally different from writing a package — data never leaves memory.

---

## Phase-Based Workflow (All Languages)

### Phase A: Data Loading & First Inspection

Load all datasets at once. Inspect shapes, dtypes, missing value counts, summary statistics.

**Principle**: This phase loads everything you'll need for the entire EDA. After this, all data lives in the REPL namespace.

### Phase B: Grid Data Exploration

Explore the 3D grid:
1. **Vertical profiles** — mean of each variable at each altitude level
2. **Horizontal slices** — variable values at specific altitude levels
3. **Terrain elevation** — spatial pattern, min/max/mean
4. **Zonal mean** — variable vs latitude (mean across longitude)

### Phase C: Network Topology

Analyze the node-edge graph structure:
1. **Degree distribution** — in-degree, out-degree, total degree per node
2. **Connected components** — how many? largest/smallest sizes?
3. **Isolated nodes** — count and identify
4. **Node type / region breakdown**

### Phase D: Node-Grid Integration

Cross-reference nodes with the grid:
1. **Elevation lookup** — nearest grid cell for each node
2. **Elevation residual** — node vs grid elevation (RMSE, bias, outliers)
3. **Temperature residual** — measured vs grid model (RMSE, outliers)
4. **Spatial autocorrelation** — do nearby nodes have similar residuals?

### Phase E: Edge Analysis

Analyze edge attributes:
1. **Weight vs distance** — correlation, scatter with regression
2. **Elevation change** — uphill vs downhill vs flat counts
3. **Terrain factor** — distribution, correlation with weight
4. **Bottleneck edges** — high-weight edges (>75th percentile)
5. **Edge type comparison** — direct vs indirect weight distributions

### Phase F: Visualization

Generate all figures using the language's equivalent of a non-interactive backend. Save to `data/figures/`. Always close/clear after saving to avoid memory growth.

Figures: `vertical_profiles.png`, `grid_temp_slices.png`, `grid_elevation.png`, `zonal_mean_temp.png`, `degree_distribution.png`, `residual_map.png`, `residual_histograms.png`, `edge_analysis.png`, `network_graph.png`, `summary_stats.png`

### Phase G: Consolidation

Assemble all exploration into a single executable script:
- Use language-appropriate cell markers or comment blocks to separate phases
- Run end-to-end from script
- Verify all figures are generated

---

## Key REPL Principle

**Write to temp file, execute, inspect output, refine.** Never type complex code directly in `pty_write`. The REPL preserves all loaded data in memory across all phases — this is the fundamental advantage over writing a standalone package.

### Iterative Refinement Pattern

```
1. Write exploratory code to temp file
2. Execute via language's include/exec pattern
3. pty_read() → inspect output
4. Find something interesting or problematic
5. Edit temp file to refine
6. Repeat until satisfied
7. Move working code to consolidated script
```

## Key Insight: REPL vs Package

In a package, each function loads its own data or accepts data as arguments. In REPL EDA:
- Data is loaded ONCE and lives in the REPL namespace
- Subsequent steps reference already-loaded variables
- Exploration is non-linear — you go where the data tells you
- Intermediate findings inform the next step's approach
- This is what makes REPL EDA fundamentally different from pipeline EDA
